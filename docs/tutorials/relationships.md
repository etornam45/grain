# Relationships

This tutorial extends the [Getting Started](getting-started.md) project with a
related table and shows off the parts of Grain that shine once you have more
than one table: foreign keys, join queries, grouped counts, and transactional
deletes.

## 1. Add an `orders` table

Foreign keys go through `.References(col)` plus optional `.OnDelete`/`.OnUpdate`.

`internal/schema/schema.go`:

```go
var Orders = schema.Table("orders",
    schema.Column("id", schema.Serial()).PrimaryKey(),
    schema.Column("user_id", schema.UUID()).
        NotNull().
        References(Users.Col("id")).
        OnDelete(schema.Cascade),
    schema.Column("total", schema.Numeric(10, 2)).NotNull(),
)
```

`.References(Users.Col("id"))` emits
`FOREIGN KEY (user_id) REFERENCES users(id)` and `.OnDelete(schema.Cascade)`
adds `ON DELETE CASCADE`.

Generate and apply:

```bash
grain generate -schema internal/schema "add orders table"
cat db/migrations/$(ls -t db/migrations | head -1)
```

```
-- +migrate Up
CREATE TABLE orders (
  id SERIAL,
  user_id UUID NOT NULL,
  total NUMERIC(10,2) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
...
```

```bash
grain migrate up
```

> Note how the migration generator ordered the new table after the one it
> references and pulled the FK into `CREATE TABLE`. If two new tables
> referenced each other it would stop with a cycle error instead.

## 2. Create a user with a couple of orders

`Serial()` IDs are generated by the server; capture them through `Returning`.
We'll also use a transaction so the user and their orders land atomically:

```go
err := conn.Transaction(ctx, func(tx *db.Tx) error {
    var userID string
    if err := query.Insert(schema.Users).
        Values(map[string]any{
            "name":   "Kofi",
            "email":  "kofi@example.com",
            "status": "active",
        }).
        Returning(schema.Users.Col("id").String()).
        Scan(ctx, tx, &userID); err != nil {
        return err
    }

    var orderID int
    if err := query.Insert(schema.Orders).
        Values(map[string]any{
            "user_id": userID,
            "total":   149.99,
        }).
        Returning(schema.Orders.Col("id").String()).
        Scan(ctx, tx, &orderID); err != nil {
        return err
    }
    fmt.Printf("inserted user %s with order %d\n", userID, orderID)
    return nil
})
if err != nil {
    log.Fatal(err)
}
```

## 3. Join queries

Join results scan into a struct tagged with the **qualified** column names. The
scanner matches each result column to a tag (`users.name`), so joins never
silently misassign columns.

```go
type bigOrders struct {
    UserName string `db:"users.name"`
    UserID   string `db:"users.id"`
    OrderID  int    `db:"orders.id"`
    Total    string `db:"orders.total"`
}

rows, err := query.Select[bigOrders](
    schema.Users.Col("id"),
    schema.Users.Col("name"),
    schema.Orders.Col("id"),
    schema.Orders.Col("total"),
).
    From(schema.Users).
    InnerJoin(schema.Orders, query.Eq(schema.Users.Col("id"), schema.Orders.Col("user_id"))).
    Where(query.Gt(schema.Orders.Col("total"), 100)).
    OrderBy([]string{schema.Orders.Col("total").String()}, query.Desc).
    All(ctx, conn)
if err != nil {
    log.Fatal(err)
}
for _, o := range rows {
    fmt.Printf("%s (%s) — order #%d for %s\n", o.UserName, o.UserID, o.OrderID, o.Total)
}
```

Joins compose with everything else: `LeftJoin`, `RightJoin`, `FullJoin`, and
`CrossJoin` behave the same way.

## 4. Grouped counts

`SelectBuilder.Count` wraps your whole query in `SELECT COUNT(*) FROM (...)`
and returns a total as an `int64`:

```go
total, err := query.Select[struct{}](schema.Orders.Col("id")).
    From(schema.Orders).
    Count(ctx, conn)
if err != nil {
    log.Fatal(err)
}
fmt.Println("total orders:", total)
```

For per-group counts you need raw SQL (aggregates like `COUNT(*)`), while
`Select` accepts only column references. A tiny type that exposes `String()`
satisfies the same interface, so you can paste any expression into the select
list — and `GroupBy`/`Having` already take raw strings. Declare the helper type
at package level, then use it inside your function:

```go
type rawCol string
func (c rawCol) String() string { return string(c) }

type statusCount struct {
    Status  string `db:"users.status"`
    N       int64  `db:"n"`
}
```

```go
byStatus, err := query.Select[statusCount](
    schema.Users.Col("status"),
    rawCol("COUNT(orders.id) AS n"),
).
    From(schema.Orders).
    InnerJoin(schema.Users, query.Eq(schema.Users.Col("id"), schema.Orders.Col("user_id"))).
    GroupBy(schema.Users.Col("status").String()).
    All(ctx, conn)
if err != nil {
    log.Fatal(err)
}
for _, s := range byStatus {
    fmt.Printf("%-10s %d\n", s.Status, s.N)
}
```

The result columns are `users.status` and `n`, and the tags (`db:"users.status"`,
`db:"n"`) match them exactly.

## 5. Transactional deletes with CASCADE

`orders.user_id` is `ON DELETE CASCADE`, so deleting a user removes their
orders in the database. Still, wrapping multi-step deletes in a transaction
keeps things atomic — and every query accepts a `*db.Tx` as its executor:

```go
userID := "00000000-0000-0000-0000-000000000000" // the ID from step 2

err = conn.Transaction(ctx, func(tx *db.Tx) error {
    // Explicitly remove orders first (defensive; CASCADE would handle it).
    if _, err := query.Delete(schema.Orders).
        Where(query.Eq(schema.Orders.Col("user_id"), userID)).
        Run(ctx, tx); err != nil {
        return err
    }
    if _, err := query.Delete(schema.Users).
        Where(query.Eq(schema.Users.Col("id"), userID)).
        Run(ctx, tx); err != nil {
        return err
    }
    return nil
})
if err != nil {
    log.Fatal(err)
}
fmt.Println("user and orders deleted atomically")
```

If the second delete fails, the first is rolled back — the user's orders
survive.

## 6. A note on multi-table inserts and unique violations

`Insert`'s column list is sorted alphabetically, so the same map always
produces the same SQL. Watching for `email` uniqueness is up to PostgreSQL —
the `unique` constraint on `users.email` becomes a database error you can
handle:

```go
err := query.Insert(schema.Users).
    Values(map[string]any{"name": "Ama", "email": "ama@example.com"}).
    Run(ctx, conn)
if err != nil {
    // duplicate key value violates unique constraint "users_email_key"
    log.Println("could not create user:", err)
}
```
